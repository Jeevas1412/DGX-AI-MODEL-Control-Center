# Windows 安装包与干净环境验收计划（C-09.5）

状态：🔄 当前用户 NSIS 安装器已生成；待干净环境安装/卸载与代码签名。  
目标：把现有 React 界面与本机 Node 后端交付为当前用户可安装、可卸载、无需终端常驻的软件。

## 首版选型

首版采用 **Electron + electron-builder（NSIS 当前用户安装）**：

- Electron 主进程复用现有 Node 运行时，在本机启动受限后端，而不是要求用户另装 Node 或打开 PowerShell。
- 渲染窗口加载由本机后台提供的已构建前端，以同源方式访问 API；不以关闭浏览器安全策略来绕过 CORS。
- `contextIsolation` 保持开启，`nodeIntegration` 关闭；网页层没有文件系统、SSH 或子进程权限。
- 安装范围为当前 Windows 用户，程序和数据分离；卸载默认保留连接元数据与审计，界面提供“同时删除本机数据”的明确选项。
- 现有开发期计划任务和 Vite 启动脚本不打入正式安装包；产品版使用受控的桌面应用自启动/托盘生命周期。受保护 LAN 仍是默认关闭的可选功能。

该选型能直接复用当前 Node 22 后端和 Windows OpenSSH 调用链，避免在首版额外引入 Rust、Node sidecar 或浏览器权限绕行。正式依赖版本在实现分支锁定后写入 lockfile。

## 安装后的目录与数据边界

```text
%LOCALAPPDATA%\Programs\DGX AI Control Center\   安装的应用文件
%LOCALAPPDATA%\DGX AI Control Center\             用户连接元数据、审计、可恢复日志
```

- 应用目录不得写入 Token、密码、私钥、DGX 地址或远端路径。
- 连接配置仅保存显示名、OpenSSH 别名、可选指纹记录和时间戳；私钥仍由用户既有 Windows OpenSSH/凭据机制管理。
- LAN 查看令牌由独立的 Windows 受保护存储处理；不得复制到 renderer、安装日志、崩溃报告或导出文件。
- 安装包不部署远端适配器；HY MT2 适配器必须在应用内显示版本、影响和确认信息后，走专用事务。

## 首次运行

1. 点击桌面入口，应用在回环地址启动本机 API，并显示连接向导。
2. 用户填写显示名称和已存在的 OpenSSH 别名；界面保存受限元数据后，运行固定只读能力验证。
3. 若验证失败，只显示可读的本机问题分类；不显示命令、远端路径或原始错误。
4. 能力可用时进入只读监控；HY MT2 控制仍显示为“未安装适配器/不可执行”，直到 C-09.3 与 C-09.4 完成。
5. 用户可选择“登录后启动并最小化到托盘”；默认不启用 LAN，启用时要求明确确认并执行受保护网络检查。

## 交付物拆分

| C-09.5a | Electron 壳与同源生产静态托管 | 打包后不依赖 Vite、PowerShell 或系统 Node；renderer 无 Node 权限。 |

| C-09.5c | 首次运行与自启动 | 向导、托盘、登录启动开关可用；退出时本机后台受控退出。 |
| C-09.5d | 干净环境验收 | 未配置过项目的同类 Windows 机器完成安装、别名验证、只读页面与卸载验证。 |

## 干净环境验收清单

1. 使用无项目源代码、无开发 Node/Vite 的普通 Windows 用户账户。
2. 安装后检查应用能启动、仅监听回环、页面无控制权限。
3. 在用户已配置且受信任的 OpenSSH 别名条件下，完成别名保存与固定只读验证。
4. 验证关闭、重新打开与登录自启动不会留下重复进程或端口占用。
5. 验证卸载不会删除 `.ssh`、Windows 凭据或其他应用数据；选择删除本机数据时仅删除本产品数据目录。
6. LAN 选项默认关闭；若另行验收，确认令牌、Private 网络和最小防火墙范围仍有效。

- 不在没有 C-09.3 专用适配器实机验收前暴露 HY MT2 的真实切换按钮。
