# 产品版本与环境治理基线

本文件自 2026-07-21 起为 DGX AI Control Center 的强制发布基线，来源于 Obsidian 中的《产品版本环境隔离实操手册（从 0.0.0 到 1.0.0 全周期）》。任何版本更新、安装包构建、环境切换或发布都必须遵守本文件。

## 三条独立轴

| 轴 | 当前规则 |
|---|---|
| 版本 | 使用 SemVer；当前 `0.1.0`，不得在未满足发布门槛时标称为 `1.0.0`。 |
| 环境 | `development`、`test`、`staging`、`production` 分别拥有独立 userData 目录。 |
| 分支 | 当前工作区尚未初始化 Git；初始化后最少使用 `main` 与短命 `feature/*`，发布候选使用 `release/<version>`。 |

## 物理隔离

- Electron 运行时由 `DGX_CONTROL_CENTER_CHANNEL` 决定目录；未指定时，源码运行默认 `development`，打包应用默认 `production`。
- 连接资料、偏好、审计、历史和操作账本只写入该环境自己的 userData 目录。
- 生产环境默认不启用远端只读/控制会话；用户必须在 UI 中重新建立并验证资料。
- 密钥、密码、私钥、API token 和真实 SSH 别名不进入仓库、版本清单或环境模板。

## 构建与晋级

1. 在隔离工作区完成测试与构建；产物只构建一次。
2. 将文件名、SHA-256、来源、构建时间和验收状态写入 `release/manifests/<version>.json`。
3. Test、Staging 与 Production 只能推广同一 hash 的产物，不得在环境之间重新编译。
4. Production 的安装、局域网暴露、真实 DGX 控制和更新均须人工确认；仅完成构建不等于生产验收。
5. 只有完成干净安装、核心连接/监控验收、卸载/数据保留检查、回滚演练和发布审阅后，版本才能从 `candidate` 改为 `released`。

## 回滚

- 回滚只能选择此前已记录 SHA-256 的安装包。
- 环境用户数据不会被新版本覆盖；涉及迁移时先复制、校验、再原子切换。
- 任何真实 DGX 控制失败时，应用回滚与 DGX 服务恢复须分别记录并分别验收。
