# 阶段 7：可安装产品与受控 UI 操作计划

日期：2026-07-20  
状态：✅ 架构与任务拆分完成；尚未新增 DGX 写操作

## 产品目标

将当前“本机只读监控项目”演进为 Windows 可安装软件：用户在安装向导中完成一次连接配置，之后通过图形界面查看状态、执行经确认的受控操作、查看进度与回滚结果，而不再需要运行 PowerShell、SSH 或项目脚本。

目标环境是“Windows 控制电脑 + 可 SSH 访问的 DGX”的同类部署。软件不能打包或复制用户的私钥、密码、DGX 地址、令牌或现有模型脚本；安装后由向导在本机建立连接配置。

## 目标架构

```text
Windows 安装包 / 桌面应用
        │
        ├─ 首次运行向导：连接资料、SSH 指纹确认、能力检查
        ├─ React 操作界面：只显示受控动作，不显示终端
        └─ 本机控制后台：认证、计划、审计、进度、回滚
                                     │
                              SSH 最小权限适配器
                                     │
                         DGX 已登记的服务能力与固定动作
```

前端永不持有 SSH 私钥、密码、任意命令能力或远端脚本路径。凭据仅由本机后台通过 Windows 受保护的凭据存储使用；局域网模式默认仅查看。经明确授权时，受保护 LAN 可在 Bearer 令牌与精确 CORS allowlist 下完成“创建 OpenSSH 别名资料、固定只读验证、设为当前资料”三项 Setup 动作；服务和模型控制操作仍仅限本机受认证操作者。

## 安装与首次运行体验

1. 用户安装桌面软件，安装程序创建当前用户后台服务与桌面入口。
2. 首次启动显示“连接 DGX”向导：填写显示名称和已存在的 OpenSSH 别名，记录可选指纹后点击“测试连接”。首版不要求在页面填写地址、端口、密码或密钥。
3. 软件只读发现可识别的服务与能力，显示兼容性结果；没有通过检查时给出界面化说明，不要求用户输入命令。
4. 对需要远端准备的功能，软件显示“安装受控适配器”按钮。该按钮只能部署版本化、签名/哈希校验的固定适配器，不提供远程终端或任意脚本输入。
5. 完成后，后台随用户登录自动启动，桌面软件可直接打开监控与操作页面。

## 受控操作模型

所有实际操作采用“计划 → 明确确认 → 执行 → 验证 → 审计/回滚”事务，而非按钮直接拼接 SSH 命令：

1. `POST /api/control/plans` 仅接受已登记的动作 ID 和结构化选项，生成只读执行计划。
2. 后台执行前置检查：连接、服务能力、活动请求归零、资源准入、配置快照与哈希一致性。
3. UI 在任何实际执行前先发出“操作待确认”提示，并展示动作名称、目标服务/模型、影响范围、停机范围、资源变化、回滚点、风险、预计时长与计划失效时间；操作者进行二次确认。
4. `POST /api/control/operations/{id}/confirm` 只能确认未过期、未变更的计划。
5. 后台调用固定适配器动作，持续返回无敏感进度；完成后读取健康状态并写入本地只追加审计。
6. 任一前置或后测失败即停止并进入已定义的回滚/人工处理路径。

### 操作前告知与执行反馈

控制界面不得把“已创建计划”误显示为“正在执行”，也不得在用户未看到操作说明时启动后台动作。每个受控操作必须按以下可见状态推进：

1. **待确认**：创建计划即显示桌面内提示；用户可打开计划详情、取消或确认，尚未触及 DGX。
2. **执行中**：确认后立即显示阶段、已用时、预计剩余时间或“正在等待远端响应”的真实说明；没有可靠预计时间时不得伪造倒计时。
3. **完成／失败／已回滚**：显示后测结果、实际影响、下一步与可查看的本地审计记录；失败不会自动再次执行。

通知只表达已经由后台验证的状态，不以通知替代二次确认。设置页应允许关闭非关键完成提示，但不得隐藏待确认、失败、回滚、连接中断或资源准入拒绝等关键告知。

接口只允许动作白名单，例如 `hy-mt2.switch-from-nvfp4`；不得接受 shell、路径、环境变量、Docker 参数、任意 URL 或自定义命令文本。

## HY MT2：首个端到端试点

HY MT2 作为首个 UI 化控制试点，目标不是“无条件启动”，而是让用户在 Models 页面完成一次可理解、可中断、可回滚的模型切换：

1. 读取 HY MT2 实际状态与现有主推理模型状态。
2. 用户点击“切换到 HY MT2”，先获得计划预览。
3. 后台检查请求数为零、单一推理模型策略、配置快照、远端能力版本和资源条件。
4. 用户确认后，后台按固定适配器顺序执行切换并轮询就绪状态。
5. UI 展示“准备中 / 切换中 / 就绪 / 失败已回滚”等真实进度。
6. 后测失败时恢复到计划建立时的已知基线，并提供审计记录与可读故障摘要。

首版不允许从 LAN 浏览器远程执行切换；也不允许“启动 HY MT2 但保留已加载 Qwen/NVFP4”的并存路径。把 Qwen/NVFP4 切换到 HY MT2 和切回基线定义为两个显式、可审计动作。

## 本阶段禁止项

- 不新增浏览器 SSH 终端、任意命令 API、任意文件上传/编辑或 Docker 控制入口。
- 不在前端、安装包、日志或导出文件中保存私钥、密码、访问令牌或远端路径。
- 不将当前受保护 LAN 的查看令牌升级为操作权限。
- 不在 C-09.3 的只读基线完成前实现 HY MT2 的实际启动/停止请求。
- 不承诺对未识别的 DGX 部署“一键控制”；先显示兼容性诊断和所需适配器版本。
