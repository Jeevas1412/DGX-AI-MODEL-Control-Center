# 通用服务适配器支持合同

适用版本：`0.1.0` 及后续公开候选。本文定义产品如何安全地识别、登记和控制已配置的模型服务。

## 产品默认边界

- 产品不内置任何特定模型名称、模型目录、端口、远端脚本、镜像地址或目标机器配置。
- “本地模型发现”只读取当前已验证目标上既有的模型目录与缓存；发现模型不等于可启动模型。
- 只有目标上已存在、版本固定、摘要校验通过且与服务模板兼容的适配器，才会使模型服务进入“可登记/可操作”状态。
- 用户界面不能输入或传递任意 SSH 命令、路径、端口、容器参数、镜像地址或下载 URL。

## 适配器支持包的最小交付物

每个可公开支持的适配器必须由独立审阅的版本化发布提供，至少包含：

1. 严格合同化的 `manifest`：模板、受支持模型标识、允许动作、健康检查与资源预算；
2. 固定启动资产及其 SHA-256；
3. 固定停止、重启、预热和健康复核语义；
4. 资源、队列、已验证目标与二次确认门禁；
5. 单元测试、集成测试、变更日志与回滚说明。

支持包不得根据用户输入拼接远端命令，也不得把某一台开发设备上的资产当作跨环境默认值。

## 用户可见流程

1. 连接并验证目标；
2. 在模型库读取该目标已有模型；
3. 将需要管理的模型建立为本地配置草稿；
4. 选择通用服务模板；
5. 系统读取并校验该目标已安装的适配器；
6. 通过预检后登记服务；
7. 每次预热、重启、停止或参数写入均创建计划、要求用户确认，并在执行后复核状态。

如果第 5 步没有找到兼容适配器，产品必须明确显示“已发现但当前不可控制”；不得显示假按钮、伪造端口或假装已加载。

## 发布约束

实验性模型、当前机器路径、私有模型清单、临时控制脚本和针对单一环境的操作记录必须存入本地测试档案，而非公开安装包或默认产品逻辑。任何新增支持包均需独立审阅并通过干净 Windows 11 持久虚拟机验收后，才可随公开版本交付。
# 目标支持包补充合同

公开产品默认不包含任何特定 DGX 的账号目录、模型目录、日志文件、端口或服务名。需要读取目标本地模型清单、服务健康状态或日志时，使用已审阅的目标支持包；其机器可读描述遵循 `backend/src/target-support-profile.mjs`。

- 支持包只在已验证目标的固定目录内读取，不能由网页 API 直接上传、拼接或修改；
- 描述只允许 `$HOME` 相对文件路径、数值端口、HTTP 本地健康路径和展示名称；不允许命令、shell 片段、URL、凭据、任意环境变量或当前账户绝对路径；
- 产品向 UI 返回的仅是支持包版本、运行时计算的文件 SHA-256 摘要、服务展示名、端口和“是否有日志”，不会返回远程文件路径；
- 后续 C-24 将实现 UI 的导入、摘要验证与激活；在该步骤完成前，空环境保持“未配置支持包”的安全降级，不伪造服务数据。
