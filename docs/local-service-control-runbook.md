# 本地页面四项服务受保护控制手册

## 范围

本功能只允许在部署控制中心的这台 Windows 电脑上操作四个登记服务：

| 服务 | 预热 | 重启 / 停止的前置条件 |
|---|---|---|
| NVFP4（8091） | 请求固定 `/warmup`，按现有 lazy proxy 行为加载后端 | 指标中的运行中和排队请求都必须为 0，且对应端口没有活动 TCP 连接 |
| VLM（8003） | 请求固定 `/warmup` | 代理和后端端口均没有活动 TCP 连接 |
| 图像服务（8188） | 请求固定 `/warmup` | 代理和后端端口均没有活动 TCP 连接 |
| API 兼容代理（8093） | 仅做 `/healthz` 检查；它没有独立模型可预热 | 8093 没有活动 TCP 连接 |

不接受服务名称、命令、路径、端口或 SSH 参数的浏览器输入。局域网其他设备仍只能查看受令牌保护的监控数据，不能创建或确认控制计划。

## 页面操作

1. 在本机打开 Overview 并刷新页面；页面从后端读取控制能力后，四张服务卡的三个按钮可用。
2. 点击“预热”“重启”或“停止”。页面只会创建一个有效期 5 分钟的计划，不会立即操作 DGX。
3. 检查服务、动作、风险、空闲要求和摘要，再点击“确认并执行”。
4. 页面显示固定动作的排队、执行、健康复核与完成/失败状态。执行期间其他服务按钮会锁定。

重启和停止是高影响动作。即使先前已授权，仍应在没有用户请求、队列和活动连接时逐次确认；不要把一次确认理解为后续操作的永久授权。

## 安全与审计

- 后端仅为固定服务生成固定远程脚本，并按操作互斥执行。
- 失败时停止在已知状态，不会执行未登记的“猜测性补救命令”。
- 每次已确认操作写入本地 `backend/data/local-service-control-audit.jsonl`；记录不包含令牌、密码或 SSH 私钥。
- 已完成操作后自动重新读取监控快照；若失败，请查看审计记录和服务健康，再决定下一步。
